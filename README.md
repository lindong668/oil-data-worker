## B8 变更（2026-10-28）— 黄金三源 + 每分钟抓取 + 现抓端点

### 1. 黄金：两个源 → 三个源，且循环重试 2 轮

顺序：**xaus.com（主） → biquote.io（备） → api.gold-api.com（兜底）**

为什么把 biquote 放在第二位：
实测三轮对比里，xaus 与 gold-api 的偏差恒为 **0.000%**，几乎可以肯定同源 ——
主源挂掉时 gold-api 大概率跟着挂，那级备用等于白设。
biquote 走的是 MetaTrader 5 券商报价链路，与前两者完全不同路，
才是真正在主源挂掉时能救命的那个。

**循环 2 轮**：三个源按序试完仍全灭 → 歇 1 秒 → 从主源重新开始再试一轮。
网络抖动常常是瞬时的，兜底失败的那一刻主源可能已经恢复了。

### 2. cron：每小时 2 次 → 每分钟

Cloudflare 定时任务最快就是 1 分钟，没有秒级。
要让黄金能分钟级更新，cron 必须改成 `* * * * *`。

⚠️ **原油必须加相位锁**（已加）：
原油 API 有 50 次/天硬上限，国内油价 100 次/天。
代码里加了 `isOilPhase = (min === 5 || min === 20)`，
原油与国内油价仍然只在 :05 和 :20 触发 —— **与 B7 完全一致，配额消耗不变**。

### 3. 新增 `/gold/live` —— 现抓端点

与 `/data` 的区别：

| 端点 | 行为 |
|---|---|
| `/data` | 读 KV，给的是「上次定时抓到的」（最多旧 1 分钟） |
| `/gold/live` | **当场真的去源站抓一次**，给的是此刻的价 |

2 号前端在自己实时链路全挂时要的是后者 ——
另一条路能不能通，而不是旧货。

⚠️ 需要 `X-Access-Key`。只能由 2 号 Worker **服务端**转发调用，
前端 JS 直接调会把密钥暴露在页面源码里。

### 4. 三个源的性质（页面文案已如实标注）

| 源 | 性质 |
|---|---|
| xaus.com | 指示性现货中间价，自带 fresh/stale 契约 |
| biquote.io | 券商 MT5 报价（bid/ask 中点），实时 |
| api.gold-api.com | 指示性现货价，无买卖盘 |

三者实测最大偏差 **0.037%**（约 1.5 美元 / 4060 美元的黄金）。
**都不是交易所结算价** —— 页面统一表述为「指示性参考价」。

## B7 变更（2026-10-24）— 修复 Workers Builds 预览构建红叉

**根因**：CF 的 Workers Builds 对同一次提交跑两套构建——
生产 `wrangler deploy` 成功（绿），预览 `wrangler preview` 要求
配置中存在 `[previews]` 块，缺失即失败（GitHub 上红叉）。
与 2号 A17、5号 D16 同源。

**本站情况**：wrangler.toml 有 1 个 vars，故补 `[previews.vars]`
并把该变量写入（留空占位，preview-safe）。

**部署**：无增删 → 覆盖上传，实际只需替换 wrangler.toml。
