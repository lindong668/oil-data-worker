## B8 变更（2026-10-28）— 黄金三源 + 每 3 分钟抓取 + 现抓端点

### 1. 黄金：两个源 → 三个源，且循环重试 2 轮

顺序：**xaus.com（主） → biquote.io（备） → api.gold-api.com（兜底）**

为什么把 biquote 放在第二位：
实测三轮对比里，xaus 与 gold-api 的偏差恒为 **0.000%**，几乎可以肯定同源 ——
主源挂掉时 gold-api 大概率跟着挂，那级备用等于白设。
biquote 走的是 MetaTrader 5 券商报价链路，与前两者完全不同路，
才是真正在主源挂掉时能救命的那个。

**循环 2 轮**：三个源按序试完仍全灭 → 歇 1 秒 → 从主源重新开始再试一轮。
网络抖动常常是瞬时的，兜底失败的那一刻主源可能已经恢复了。

### 2. cron：改成【两条】，原油一行不改

```toml
crons = [
  "5,20 * * * *",   # 原油 / 国内油价 —— 与 B7 完全一致
  "*/3 * * * *"     # 黄金专用，每 3 分钟
]
```

**为什么不是一条 `* * * * *` 每分钟**：

① **分钟相等判断太脆**。原本设想用 `min === 5 || min === 20` 把原油挡回去，
但 Cloudflare cron 偶有数秒漂移，一旦落在 4:59:5x 或 5:01，
原油那一小时就会**整点静默漏抓**。交给 cron 自己选时刻反而最稳。

② **每分钟会撞穿 KV 写入配额（真正的硬伤）**。
Workers KV 免费版：写入 **1,000 次/天**（官方文档）。
黄金每抓成功一次写一次 `gold_data`，每分钟 = **1,440 次/天 > 1,000**，
超出后写入直接报错 → 大约每天下午配额耗光 →
之后 `gold_data` 全天不再更新，首屏数字**静默冻住**。

改成两条 cron 后：黄金 **480 次/天** + 原油约 25 + 历史/国内油价约 25 ≈ **530 次/天**，
离 1,000 上限留有一倍余量。

**为什么黄金是 3 分钟而不是 1 分钟**：
3 号这层本来就是**兜底 + 首屏**，真正的实时跳动由 2 号前端
在浏览器里直连 biquote 完成（秒级）。兜底旧 3 分钟没有可感知差别。
想改 2 分钟：把 `*/3` 改成 `*/2`（720 次/天，仍在配额内），不建议再快。

### 3. 新增 `/gold/live` —— 现抓端点

与 `/data` 的区别：

| 端点 | 行为 |
|---|---|
| `/data` | 读 KV，给的是「上次定时抓到的」（最多旧 3 分钟） |
| `/gold/live` | **当场真的去源站抓一次**，给的是此刻的价 |

2 号前端在自己实时链路全挂时要的是后者 ——
另一条路能不能通，而不是旧货。

⚠️ 需要 `X-Access-Key`。只能由 2 号 Worker **服务端**转发调用，
前端 JS 直接调会把密钥暴露在页面源码里。

### 4. KV 写入失败不再拖垮整次抓取

`gold_data` 的写入单独兜一层 try/catch：
万一真撞上配额，也不会让「写不进去」变成「这次抓取整个失败」——
价已经拿到了照样返回，只是标注 `persisted: false` 便于排查。

### 5. 三个源的性质（页面文案已如实标注）

| 源 | 性质 |
|---|---|
| xaus.com | 指示性现货中间价，自带 fresh/stale 契约 |
| biquote.io | 券商 MT5 报价（bid/ask 中点），实时 |
| api.gold-api.com | 指示性现货价，无买卖盘 |

三者实测最大偏差 **0.037%**（约 1.5 美元 / 4060 美元的黄金）。
**都不是交易所结算价** —— 页面统一表述为「指示性参考价」。

### 6. 后台看板文案同步（B8 补）

`/`（看板页）里黄金区块原先沿用 B6 时代的旧文案：

```
📅 每日参考价（延迟日更，非盘中实时）
数据源：MetalpriceAPI 免费档（延迟约24h）
```

MetalpriceAPI 在 B7 就已彻底移除，这段描述与代码实际行为完全不符。已改为：

```
⚡ 现货参考价（每 3 分钟采集，三源互为备用）
本次命中数据源：xaus.com（主）/ biquote.io（备用）/ api.gold-api.com（兜底）
备用链路：xaus → biquote → gold-api，失败后循环重试 2 轮
```

页脚「每小时更新」一并改为「每 3 分钟采集一次」。
原油区块文案未动（原油确实仍是每小时）。

## B9 变更（2026-10-28）— 修复两条 cron 串台（原油被多抓 / 收盘价污染）

### 现象
B8 上线后发现原油在 **:09** 等非 5/20 时刻也抓了一次。
B8 声称「原油行为与 B7 完全一致」，这句话是错的。

### 根因
B8 把 cron 改成两条：

```toml
crons = [
  "5,20 * * * *",   # 原油
  "*/3 * * * *"     # 黄金
]
```

但**两条 cron 共用同一个 `scheduled()` 函数，而函数里没有任何分流**：
`*/3` 每次唤醒时，原油那套逻辑也照跑不误。

后果有两层：

1. **原油被多抓**：本该只在 :05 / :20，实际每 3 分钟都被触发，配额白白消耗。
2. **历史走势被污染（更严重）**：
   `cronPhase() = getUTCMinutes() < 10 ? 'open' : 'close'`
   这套判断是 B7 专为 5(open) / 20(close) 设计的。
   `*/3` 带来的 12 / 15 / 18 等分钟会落进 `'close'` 分支，
   于是把盘中价当成收盘价记进历史曲线。

### 修复
`scheduled()` 开头先判断【本次是哪条 cron 唤醒的】，再决定跑什么：

```js
const cronSpec = (controller && controller.cron) ? String(controller.cron) : '';
const isGoldTick = cronSpec
  ? cronSpec.indexOf('*/3') !== -1   // 明确来自黄金那条
  : (min % 3 === 0);                 // 兜底：按分钟分流

if (isGoldTick) { ...跑黄金...; return; }   // ★ 只跑黄金，绝不碰原油
// 以下只会在 "5,20" 这条上执行
```

**兜底为什么可靠**：`"5,20"` 的两个值（5、20）都不是 3 的倍数；
`"*/3"` 的全部取值都是 3 的倍数。**两个集合完全不重叠**，
故 `min % 3` 能 100% 分开。已用脚本遍历 0-59 验证无交集。

### 配额复核（修复后）
```
黄金 480 次/天 + 原油约 25 + 国内油价 2 ≈ 507 次/天
KV 免费版上限 1,000 → 留一倍余量，安全
```

### 部署
覆盖上传，实际只需替换 `src/index.js`（wrangler.toml 的 crons 不变）。
